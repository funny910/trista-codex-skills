# 方法库三：分镜与验收

**【通用方法草案 v0.1】** 用于规划方案与检查，不代表已经完成画面生成、播放或审美验收。下列方法可帮助生成选项，具体偏好与阈值仍需用户确认；真实项目效果尚未验证。

SH 是叙事镜头，CLIP 是未来制作的片段安排，仅在本轮需要制作交接或片段规划时启用。只做分镜时省略 CLIP 编号、分组表及相关检查，不强制填写平台参数。方法、示例与通用检查不能覆盖 U01–U03 或项目已确认决定。

已确认 U03：按具体故事比较叙事方案，不设统一偏好。下列涉及 U03 的问题仅在项目中按需讨论，已明确的项目取舍直接复用。

<a id="v01"></a>
## V01 · 从镜头作用选择观看重点

- **解决问题：** 分镜只有景别和画面描述，缺少“为什么这样看”的依据。
- **适用：** 事件已经确定，需要决定画面突出人物、动作、物件还是空间。
- **不适用：** 为展示技巧强行增加镜头；固定轮换景别；把某种镜头当成所有情绪的唯一解法。
- **操作：** 先读取 U07 的项目画幅决定；未指定时结合观看用途与故事建议画幅并说明构图影响，由用户选择，未选择前相关构图保持候选。写出该镜头要让观众理解或感受到的具体变化，再比较能完成这一作用的构图与观看距离。说明选择的代价，例如细节增强会减少空间信息；当前方案已满足明确要求时不必额外提出备选。
- **示例：** 同一“放下风车”的动作，中景便于保留人物与门的关系；物件近景突出动作细节，但需要其他画面提供空间依据。两者均可作为方案，不预设哪种更高级。
- **反例：** 叙事作用只写“推动剧情”；没有依据却要求每场必须有一定比例的炫技镜头。
- **检查：** 作用具体；画面承载该信息；选项改变了表达方式而没有偷偷改动重要情节；计划镜头不过度重复同一信息。
- **传递：** 镜头作用写入 SH，所需细节回到 AST 需求，沿用相关 S01 及项目决定。
- **【待你确认 U03 / U04 / U08】** 镜头表达的偏好和审美案例；不同方案之间的接受标准。

<a id="v02"></a>
## V02 · 动作衔接、空间与调度

- **解决问题：** 单镜头描述清楚，但连起来动作重复、位置跳变或视线不对应。
- **适用：** 对话、移动、取放物品及其他跨镜头连续动作。
- **不适用：** 把连续性规则用于禁止所有有意设计的跳切；用户已明确允许的风格化断裂无需机械修正。
- **操作：** 对每个衔接写出前镜结束、后镜开始的姿态、位置、动作进度及道具状态，核对观看方向。连续性变化若有叙事理由，说明观众如何理解；无依据的变化列为问题。
- **示例：** 前镜已经完成风车离手，后镜从风车在门边开始；若后镜又从手中放下，检查是否重复动作，除非这是用户确认的重放表达。
- **反例：** 角色尚未走过门口，下一镜已在门另一侧；一只道具变为两只却无人说明。
- **检查：** 动作有起止关系；运动、视线和道具状态有依据；有意跳跃与意外错误分开。
- **传递：** 调整关联 SH，以及已启用的 CLIP 接点；只有空间设计本身变化时才更新 A03，不无条件重做场景。
- **【待你确认 U03 / U08】** 对跳切、动作省略和空间跳跃的接受范围。通用原则只用于指出问题，不自动否决风格化方案。

<a id="v03"></a>
## V03 · 时长估计与镜头、片段对应

- **解决问题：** 台词和动作放不进计划时长，或按生成片段长度反过来硬切故事。
- **适用：** 需要节奏或时长规划；未来可能按片段制作，但当前只编制文档。
- **不适用：** 以固定字数、固定秒数保证可演完；在未核实模型能力时宣称某个时长必然可生成。
- **操作：** 按已确认 U07，项目未指定目标时长时先结合故事建议时长范围并说明节奏取舍，用户确认后再细化；已有明确目标直接复用。细化时按对白试读、动作过程、反应和停顿估时，并写明依据；可同时发生的动作与声音不简单相加。仅在本轮需要制作交接或片段规划时启用 CLIP 分组。记录镜头间重叠转场；启用 CLIP 时再记录跨片段长镜头的对应关系。
- **示例：** 放下物件与一句短对白可同时发生，估时应看两者的覆盖关系；没有实际试读或预演时写“暂估”，不写“实测”。
- **反例：** 为凑一个固定片段时长删掉关键反应；将所有短镜头各自当成必须生成的一条视频。
- **检查：** 细化时长有用户指定或确认依据；全片总时长说明重叠部分；仅启用 CLIP 时检查镜头区间与片段合计；估计误差与待测部分明确；关键内容没有因凑数而消失。
- **传递：** 时长变化更新 SH、必要的 CLIP 及依赖它的提示词时间描述；结构或重要情节变化仍按 U02 处理。
- **【待你确认 U07 / U08】** 目标时长及允许偏差；节奏与信息完整性冲突时的取舍。未确认不填固定阈值。

<a id="v04"></a>
## V04 · 图片、视频描述与素材匹配

- **解决问题：** 提示词堆积形容词，或文字描述与引用素材、动作顺序不一致。
- **适用：** 按已确认 U06，仅在项目明确需要图片或视频提示词草案时使用；只做资产清单或分镜时跳过。
- **输入入口：** 静态资产图使用第三阶段的资产规格，无需分镜或 CLIP；镜头静帧使用对应 SH；视频使用 SH 或已启用的 CLIP。只填写所需类型，不为提示词强制分组。
- **不适用：** 把草拟提示词当成生成；猜测平台专有语法或资源编号；在提示词里擅自修补未确认剧情。
- **操作：** 仅起草本项目明确需要的提示词类型，采用平台无关的文字描述，每份草案标明“尚未验证”。图片描述主体、身份、视角、姿态及构图；视频描述起始状态、动作先后、摄影机运动、结束状态及原稿明确或 U07 已选的声音与字幕要求，未选择的用途建议保留为待决定项。将每项参考绑定到真实 AST 版本，说明引用目的；冲突回到相应上游决定处理。
- **示例：** 图片规格可以描述阿禾手持风车的姿态；视频草案再描述放下、停顿、转身的顺序。若背面参考缺失，保留缺口，不写成已有素材。
- **反例：** 单张图片同时要求“走近、放下、转身并离开”；风格参考替代身份参考；写出并不存在的资源 ID。
- **检查：** 图片与视频要求区分；动作和镜头运动不冲突；关键身份与道具状态一致；未核实参数和缺失素材可见。
- **传递：** 草案引用项目决定及素材版本；上游变更仅重查受影响提示词，不自动提交生成。
- **【待你确认 U06 / U08】** 哪些提示词写法经过你的实际结果验证，哪些问题必须在提交前解决。通用写法不作为效果保证。

<a id="v05"></a>
## V05 · 分层检查、接受与局部修改

- **解决问题：** 文档写完就被标成“作品完成”，或一次反馈引发整套重做。
- **适用：** 每个阶段交付前、收到修改意见时或恢复已有项目时。
- **不适用：** 用文本检查替代实际画面播放；用通用审美偏好覆盖用户选择；将未看到的素材判为通过。
- **操作：** 分三层记录：文档与逻辑检查、实际素材检查、用户接受。按已确认 U08，先检查一致性，再将本轮约定的文档、检查结果、问题与待定项集中提交，由用户验收；U02 大纲、U04 风格和 U07 的时长、画幅、声音与字幕选择继续保留，不以集中验收推迟这些决定。每个问题注明位置、依据、影响与建议。按项目决定检查，而不是只数表格字段。修改前查 AST / SH / CLIP 的实际依赖，仅更新受影响内容。
- **示例：** 文本已明确风车始终在门边，可记录连续性规划自洽；没有真实视频时仍应写“画面连续性未执行验收”。用户只修改角色衣袖细节时，列出引用该角色版本的镜头，不改场景与结局。
- **反例：** 任务表完整就宣布成片通过；将用户对一个镜头的认可扩展为对全片或通用方法的认可。
- **检查：** 每个结论有对应证据或明确局限；结构检查、实际观察与接受状态分开；旧版接受记录不被当作新版接受；未观察项保持未检查。
- **传递：** 检查结果进入当前产物和项目工作表；确认范围、待修改项及版本传给下次续作，不自动改写个人方法。
- **【待你确认 U08】** 审美标准、可接受瑕疵及需要你亲自判断的项目。可以先按通用维度检查事实，不能先替你宣布接受。

建议按当前产物选用的检查维度：

| 维度 | 现在可以检查什么 | 仍需实际结果或用户决定什么 |
| --- | --- | --- |
| 内容 | 原稿重点、U02 边界、信息落点 | 剧情表达是否达到用户期望 |
| 角色与场景 | 规格、来源、版本、状态关系 | 实际形象与用户接受范围 |
| 镜头与节奏 | 叙事作用、动作衔接、估时依据 | 实际播放节奏与情绪效果 |
| 参考与提示词 | 引用、动作、声音和参数之间的冲突 | 实际生成适配性 |
| 交付 | 本轮文档范围、待补项和确认依据 | 当前未制作的成片及最终接受 |
