# 剧本到短片制作规划 · 个人 Skill 草稿

状态：规划文档已验收，供 Git 仓库分发；安装与实际运行效果未验证，仅支持规划和文档交付。

## 目标与使用范围

**已确认定位（U01）：** 本 Skill 以剧情类动画短片为主要应用方向，将故事或剧本整理为角色资产规划、场景资产规划和分镜方案。当前仅交付规划文档，不接入生成。

以七阶段流程组织上述规划，保留用户已经确定的剧情、审美和授权范围，使用其个人方法与案例补足创作判断。其他章节按实际规划需要选用，不自动扩大核心交付。

本版不调用图片、视频、配音、音乐生成或剪辑合成服务，不上传素材、不创建远程任务、不查询账户余额、不发布内容。即使原始参考 Skill 列出了工具，也不把它当成当前可用能力。未来接入制作需另行修改并验证本 Skill；当前文档内的参数、报价栏与任务计划均不构成执行授权。

方法库、项目决定与素材索引均使用本地文档；不建立数据库、向量索引或外部知识库服务，不依赖未提供的子技能。文件存在不代表已经安装、自动启用或实际运行。

适合：剧情类动画短片的故事或剧本拆解、角色与场景资产规划、分镜设计及局部方案修订。

用户只需要某个环节时，仅处理该环节及其必要依赖，不机械重做七阶段。已有有效成果和确认可以复用；仅重查受到变化影响的部分。

### 定位与分段读取

本规则用于方法库、U 清单及项目文档的取材；先定位再读正文，不以批量通读替代选择。

1. **明确当前问题。** 从请求和项目状态提炼当前要解决的一个问题，例如“D01 已选机器人视角，需要补哪些动作参考”；先查上方路由表，选出直接相关条目。后续阶段尚未发生的问题不提前读完整资料。
2. **只定位标题和边界。** 定位时只返回文件、位置、父章节和提取后的标题或条目编号，禁止返回完整匹配行、前后正文或整份文件。使用 `rg` 时采用 `-n -o`（行号＋仅匹配部分），并把表达式限定在真正的标题、编号或锚点字段；不能只用 `rg -n` 搜索关键词后直接输出，因为它默认带出整行正文。标题与正文同处一行时，匹配必须在标题结束处截止，不用通配表达式吞入后文。比如编号粗体标题可匹配 `^[0-9]+\. \*\*[^*]+\*\*`，再按目标标题收窄；其他工具也只返回对应的短索引字段。定位结果不算正文已读，确定范围后再单独分段读取。目标结束于下一个同级或更高层级标题之前，末条才延续到文件结尾。比如定位 A02 时，在对应文件查边界，不递归扫描三组方法库全文。行号与位置以当前文件为准，不沿用旧坐标。
3. **先消除同名歧义。** 标题重复时，用文件及版本、父章节路径、该父范围内的出现位置和必要的少量上下文共同定位；不能默认取第一处，也不能把实验中的“第二处”当作固定规则。同名子节分别保留，不以标题文本作为唯一身份合并或覆盖。现有请求和上下文仍不能确定目标时，保留候选位置并只问一个关键问题；在确定前不采用其中任一正文作结论。
4. **读取完整的相关条目。** 按已确认的定位范围分段读取，不能越界混入相邻条目。首次使用某份方法资料时，补读首条前的通用说明，已经完整读取且未变的说明可复用。不要只摘操作步骤而漏掉适用、不适用、检查、传递和待确认内容。
5. **按自然边界逐步缩小。** 长条目先按子标题、自然段分开；单个自然段仍超预算时再按自然句细分。记录文件、条目定位、已读范围、未读缺口和下一段位置。没有可用标点或自然句仍过长时，转入字符范围读取；不能因找不到自然边界而反复请求整段。
6. **无标点长句按字符范围续读。** 先锁定所属条目、小节及段落，再用解码后的 Unicode 字符（码点）定位段内范围，统一采用从零开始、包含起点且不包含终点的区间。不要混用字节位置、UTF-16 代码单元或显示字形数量；工具计数方式不同则先确认转换，不能猜测。字符位置仅保存在请求参数和读取记录中，不往原文插入行编号、校验值或人为结束标记。先取小窗口，返回仍不完整就继续缩小；字符数不等于 token 数，不套用固定窗口大小。
7. **限制单次正文输出并遵守预算。** 默认一次只返回一个相关条目或分段；同一决定需要多个条目时，先读完并判断第一个，再读取确有必要的下一个。不要将多份方法库、整份 Skill 和长项目文档拼到一次输出中。可批量做独立的短标题定位，但需同时考虑单个工具与外层合并返回的预算。用户或测试已经固定返回预算时保持不变，以缩小范围适配，不提高预算绕过限制；260 token 只是已完成测试的参数，不是所有任务的统一预算。
8. **截断后按缺口续读。** 出现截断提示、正文中断或预期结尾缺失时，保留部分读取状态。从最早未完整取得的位置收窄范围续读，不原样重发整条、整段，也不能把未显示内容算作已读。首尾都可见不等于中间完整；只有位置和边界确实可核对的片段才可复用，无法定位的片段保持未确认覆盖。
9. **核对边界重叠后再拼接。** 为连接新片段与已读片段，可少量重取接缝处的原文；先核对返回范围、实际字符长度及重叠文字逐字一致，再只接入新增内容。中间缺口补齐后，也核对它与保留尾段的交界。重叠应服务于定位，不扩展为重读整段；有重叠就如实记录，不能报告为零重复字符。长度、坐标或重叠文字不一致时停止该次拼接，退回最近已核实边界，检查文件版本、范围和计数方式后再缩小范围读取；不猜测补字或跳过冲突继续作完整结论。
10. **按变化复用并确认读全。** 已完整读取、仍在可用上下文中且内容未变的条目可复用；源文件改变时，旧的出现位置和字符偏移需要重新核对，不能拼接不同版本。当前问题改变或出现新依赖时再定位补读；找不到条目就说明缺口，不无边界扩大读取。应用条目前，确认相关通用说明、各分段和全部约束已经实际取得、覆盖区间没有缺口；未读完只整理已读事实，不给出完整的方法适用或验收结论。

完整剧本核对、全库审阅等任务需要覆盖全部内容时，按场次、章节或条目分批读完，并核对覆盖范围；分段只限制一次返回的内容，不能缩减用户要求的审阅范围。试跑或复核时记录实际读取的条目、边界与是否完整；日常执行不必逐条向用户播报。

以上是读取行为要求，不假定宿主提供某个专有接口。可用已有本地工具提取所需范围；工具无法定位或返回可靠片段时，明确说明缺口并暂停依赖该内容的结论，不能声称已经恢复。测试读取器、临时资料和校验结果不自动成为 Skill 的工具依赖或创作方法。

例如“第二场跟随点点，细化参考并检查连续性”：先定位并完整读取 A02，列出动作参考需求；开始核对跨镜头状态时再定位 V02。只有发现空间布局缺口才补读 A03，时长暂未涉及就不读 V03；不因此整读动画资产库和分镜库。

标记约定：

- `【待你决定 Uxx】`：需要用户作出实际创作或范围决定。
- `【待你提供 Uxx】`：需要用户提供方法、素材或案例。
- `【建议，未确认】`：可供选择的建议，不能被表述为用户偏好或验收通过。
- `【待核实】`：素材、规格或结果缺少证据，不猜测补全。
- `【通用方法草案】`：可用于提出方案，不等于用户偏好、已验证经验或验收通过。
- `【待你确认 Uxx】`：需要选择或校准的个人方法与标准；按需一次处理一个关键问题，不要求一次审核整套方法库。

## 启动规则：先判断输入，再进入阶段

**区分两种工作。** 用户要求创建、评估或修改 Skill 时，处于编写模式，处理规则及 U 清单，不将其当成一个动画项目。用户带来具体作品任务且本 Skill 已被明确指定或由宿主加载时，进入项目模式，复用已确认偏好，不重新从 U01 问到 U09。

项目启动时先从当前请求、已有文档和确认记录提取：本轮目标、输入及版本、已有成果、允许的改动、缺失决定与交付终点。用户已提供的内容直接采用；只读取与当前目标相关的文件。无法判断最新版本或存在冲突时，只暂停受影响产物，不覆盖已有成果。

| 输入状况 | 起始处理 | 可跳过的工作与边界 |
| --- | --- | --- |
| 一句创意或简短大纲 | 在阶段 1 保留已有设定，补出包含主要人物关系、关键情节和结局的大纲 | 按已确认 U02 起草，新增内容标为提案；用户确认大纲后再扩写剧本。不把方法库示例当成用户剧情 |
| 内容较完整的故事概要 | 先检查核心事件、因果与结局是否明确，再按本次目标进入阶段 2 或 4 | 已有内容可直接拆解；若必须补写重要情节，按 U02 先提建议。无需为了流程补写完整对白剧本 |
| 完整剧本 | 轻量核对 U02 边界及原文覆盖需求，然后进入资产或分镜规划 | 不重新做创意发散或大纲；必要润色按已确认权限进行，非本轮所需的润色可跳过 |
| 只有角色、场景或其他素材 | 按请求进入阶段 2 / 3，先编目与检查现有素材 | 不从图片自动推导故事；若目标是叙事分镜且缺少故事，只询问下一步所需的一个关键问题 |
| 已有分镜，要求局部修改 | 定位目标 SH、关联 AST 与已有决定，进入阶段 4 或相关检查环节 | 保留不受影响的镜头；不重做整套剧本、素材与分镜 |
| 恢复已有项目 | 读取最近的有效项目工作表及本轮涉及的输入版本，从未完成或受影响处继续 | 不重问已确认决定；历史产物保留，过期引用只标记并处理受影响项 |

首次回应简要说明本轮目标、拟进入的阶段及可复用内容。信息足够就开展已授权规划；确有关键缺口时，一次只问一个关键问题，并继续不依赖该答案的工作。第 5 阶段按 U06 仅在项目明确需要提示词时展开，第 6 阶段仅在请求需要制作交接时展开；第 7 阶段交付本轮实际完成的内容。

## 从方法库生成选项

1. **先定位一个决策。** 判断问题来自剧情、情绪、角色识别、场景空间、镜头表达或验收。已有明确决定且无相反证据时直接沿用，不为了展示知识重复出题。
2. **选方法并绑定事实。** 按“定位与分段读取”规则读完相关条目的必要内容，再将方法与当前故事或素材中的具体事实对应。通用案例只帮助解释，不作为项目事实；有适用限制则说明。
3. **给出少量可比较方案。** 通常 2–3 个方案足够；区别应落在具体的行为、构图、信息分配或资产处理上，不只换形容词。说明每个方案的依据、预期效果、代价及影响范围。可提出有理由的推荐，但不自动替用户选择，也不制造不必要的备选。
4. **检查修改权限。** 涉及核心剧情、人物关系、结局、叙事结构或重要情节的变化，标明超出有限润色范围；可以提出建议，不提前写入既定剧本。普通视觉表达方案也必须保留用户已确定的内容。
5. **一次问一个关键问题。** 用户可以选方案、修改方案、自定义或保留现状。不要把多个独立决定藏在同一个选项里；确有绑定关系时说明影响。选项已经清楚展示且用户明确选择，即视为对列明内容的确认，不再重复问“是否确认”。
6. **落地后检查。** 将选中方案记录为项目决定，传递到相关产物，再检查执行是否一致。用户只说不满意时，先定位具体问题，避免无依据地循环换方案。

建议展示格式：`方案名称 → 本项目具体怎么做 → 采用的方法与适用原因 → 预期效果与代价 → 影响哪些产物`。只呈现当前决策需要的内容，不把整套知识库输出给用户。

### 交互示例（虚构，仅演示机制）

假设已有剧本明确：阿禾将修好的纸风车放在朋友门口，停顿后离开；两人最终没有见面。本轮只选择停顿时如何组织镜头。

| 方案 | 具体表达与依据 | 效果与代价 | 影响范围 |
| --- | --- | --- | --- |
| A · 跟随人物 | 使用 S03、V01，以中景保留放下、停顿、离开的动作关系 | 行动清楚；情绪较依赖姿态的可读性 | 该场构图与表演参考 |
| B · 关注物件 | 使用 S02、V01，把已存在的纸风车与手部动作作为观看重点 | 物件意义突出；需保留足够空间信息，避免观众不知人物在哪 | 道具细节需求及该场分镜 |

只问：“这一刻你更希望观众关注阿禾的行动，还是纸风车承载的关系？”两个方案都不改变剧情事件、人物关系或结局。若提议朋友开门相见，则需另列为改变结局的建议，不能混入镜头方案。

## 决定如何传递与修订

在 [项目工作表](assets/project-workbook.md) 中记录关键决定，不另建数据库或复杂配置。采用 D01 等简短编号即可；每条包含内容、适用范围、确认依据、相关方法、影响产物与状态。候选、已确认、已替代、需重新核对分开记录。

- **确认范围要明确。** 用户在一个场景中选中某种表达，只适用于该场景；对项目风格的确认可适用于全片。项目选择不自动升级为个人默认方法，也不自动改写 Skill；只有用户明确要求保存为通用偏好时才更新个人规则。
- **按实际影响传递。** 情绪与信息目标传到剧本检查和分镜；角色身份决定传到资产规格与对应镜头；场景动线传到空间描述、调度及连续性；已选风格传到参考用途、提示词草案和检查项；交付要求传到需要的字段及最终交接。
- **开始下游工作前读决定。** 核对其适用范围、当前版本和确认状态，简要列出本产物沿用的相关决定。不能只记录一次选择而让后续阶段另起风格。
- **变更保留依据。** 用户明确改变已确认选择时，记录新决定并保留旧版本或旧记录；只把受影响的 AST / SH / CLIP 及检查项标为需重新核对。旧版曾被接受仍是历史事实，不能把它误写成新版也已通过。
- **新要求与旧决定冲突时**，明确的新要求在其范围内优先，原确认不需要重复撤销；改动范围不明确时只问一个关键问题，暂停依赖该决定的改动。

上述虚构示例若选 B，可在演示中把 D01 的范围记为“门口场景”；对应检查应验证分镜包含物件重点、空间仍可辨认、结局仍为未见面。不得将这条示例写成真实用户确认，也不得据此让所有场景都采用物件特写。

## 共同工作规则

1. **先识别请求范围。** 记录用户已有输入、当前要完成的阶段、允许的改动以及本轮交付。背景信息和参考案例不扩大任务范围。
2. **按输入与已确认权限处理文本。** 对已有故事或完整剧本，默认采用 U02 已确认的有限润色：保留核心剧情、人物关系和结局，允许润色对白、动作和环境描写；如需调整剧情结构或增删重要情节，先提出建议，经用户确认后再修改。不得借润色改变上述保留内容。用户明确只要求格式整理时保留原文字句；对一句创意或简短大纲，保留已有设定，先补出包含主要人物关系、关键情节和结局的大纲，经用户确认后再扩写剧本。未获准修改的其他内容保留原稿。标出建议与改动，不把新内容伪装成原文；无法转成画面的信息列为适配问题，不静默删掉。
3. **确认只用于真实决定。** 用户已经明确的内容不重复询问。可以先产出标注假设的草案；未经用户决定的关键剧情、风格、素材身份及验收结论保持待定，不以等待时间代替同意。
4. **原稿、资产、镜头与片段可对应。** 按需使用 SRC、AST、SH、CLIP 编号；局部修改保留编号并记录版本。仅引用真实存在的文件或链接，绝不编造资源、生成任务或确认记录。
5. **资产状态如实记录。** 区分缺失、已提供未检查、已检查待确认、已确认、需修改；已确认需有当前对话或项目记录依据。文件存在、能够打开、检查通过与用户接受是不同事实。
6. **修改只影响必要部分。** 先查该资产、原文或镜头的引用，再提出修改与受影响列表；保留原稿及已确认版本。对归属不明、无法安全保留的文件不覆盖。
7. **计划与真实结果分开。** 计划时长不冒充媒体时长，提示词不冒充生成结果，分段视频不冒充完成的成片。未运行的阶段明确写未执行。

## 第一阶段：输入整理与剧本方案

**进入条件：** 有创意、原始文字、现有剧本或明确的诊断对象。输入较少时按 U02 起草大纲，不能把补充提案写成用户已有设定。

**处理：**

- 判断采用格式整理、制作拆解与有限润色，还是创意扩写；已有原稿按共同规则第 2 条及本项目明确要求处理，其他权限不清的内容先保留，仅给出建议。
- 标出必须保留的情节、动作、对白、人物关系和结局；给需要追踪的段落设置 SRC 编号。
- 一句创意或简短大纲先补出主要人物关系、关键情节和结局，区分已有设定与新增提案；记录大纲版本及确认状态，用户确认后再扩写剧本。已有有效确认可复用。
- 将内容整理成场次、时间地点、可见动作、对白或旁白。已有完整剧本不再无条件扩写。
- 检查因果、人物动机和信息遗漏。冲突点记录为问题与选项，不擅自替用户决定主题或结局。
- 按已确认 U03 结合具体故事比较叙事方案，不设统一偏好；复用本项目已明确的取舍。通用方法标为建议，不冒充用户既定方法。
- 按问题调用 S01–S04，必要时通过上面的选项规则确定本片或本场的导演意图；将已确认的情绪目标、信息重点与保留内容写入项目决定，供资产与分镜阶段读取。

**输出：** 按当前进度交付待确认大纲或剧本草案，以及原文覆盖关系、建议改动与待决定项。

**检查：** 核心剧情、人物关系和结局按已确认要求保留；对既有内容的剧情结构调整或重要情节增删有用户确认依据；简短创意扩写剧本前有对应大纲的确认依据；未授权内容未被删改；原文重点有对应位置；新增内容可识别。

**已确认依据：** 定位 [U01](references/owner-inputs.md#u01)、已有原稿的有限润色边界及简短创意先大纲后剧本规则 [U02](references/owner-inputs.md#u02)、按具体故事比较叙事方案的规则 [U03](references/owner-inputs.md#u03)。

## 第二阶段：视觉资产拆解

**进入条件：** 剧本或当前工作片段足以识别所需视觉对象。依据未定稿剧本制作的清单须标为暂定。

**处理：**

- 按实际需要识别人物、场景、关键道具、产品及必要变体；记录首次出现和依赖的 SRC / SH 编号。
- 为每个资产写明用途、身份锚点、允许变化、来源与缺口。人物服装变化可作为同一资产的变体，不自动拆成无关联的新人物。
- 先复用已有适用素材。未提供的外貌或设计细节可以提出候选，但不伪装成原文事实。
- 项目视觉方向尚未确定时，按 U04 结合故事提供 2–3 种文字风格方案，说明效果与代价，由用户选择；已指定或已确认的风格直接复用，选择结果写入项目决定并传到资产与分镜。
- 按已确认 U05 优先复用现有适用素材，再按镜头用途列出必要的视角、表情、动作和空间参考；说明所支持的镜头或动作，不强制所有资产制作三视图或完整设定包。
- 涉及画幅的资产构图规格沿用 U07 的项目选择；未选择时标为候选，不把成片画幅套到所有角色或道具参考图。
- 按 A01–A04 将叙事用途转成角色识别、表演、空间与参考需求；读取相关项目决定，只对未确定且影响设计的事项提出选项。

**输出：** 带编号与版本的资产清单、参考需求、缺失素材列表。

**检查：** 需要跨镜头复用的身份有清晰定义；关键资产没有漏列；无关装饰不被自动升级成额外制作任务。

**已确认依据：** 文字风格方案的比较与选择规则 [U04](references/owner-inputs.md#u04)、优先复用素材并按镜头需要规划参考的原则 [U05](references/owner-inputs.md#u05)。**你的补充点：** 本项目的具体风格、参考、禁区及现有素材。

## 第三阶段：素材规格与现有素材检查

**进入条件：** 已有资产清单；如果缺少素材，本阶段仍可完成素材规格草案。

**处理：**

- 为确实需要补充的资产写设定要求；仅在项目明确需要时，按 U06 根据资产规格附上平台无关的静态资产图提示词草案并标明“尚未验证”，无需先建立分镜或 CLIP。只写必要视角与细节，不默认增加图片数量。
- 对用户已授权检查的文件，记录实际能观察到的尺寸、清晰度、视角、身份特征和可用范围。无法读取的项目标为待核实。
- 分开记录图片中观察到的事实与建议改动；给每张图标出它用于身份、构图、空间、色彩或材质参考。
- 缺图时交付素材需求，不执行生成或上传，不编造图片路径。没有实际图片时，不能通过视觉一致性验收。
- 用户已有明确接受记录且素材未变时复用，不重复要求确认。
- 使用 A02、A04 和 V05 检查“当前能看清什么、还缺什么”；通用检查建议与用户已确认标准分开，不因方法库存在就判定素材合格。

**输出：** 素材规格、现有素材检查记录与待补素材；项目明确需要时附图片提示词草案（尚未验证）。

**检查：** 实际图片与文字规格分开；合格范围与未知范围清楚；参考图不被默认为最终资产。

**已确认依据：** 按镜头需要规划参考 [U05](references/owner-inputs.md#u05)。**你的补充点：** 本项目的实际素材、图片合格标准 [U08](references/owner-inputs.md#u08)。

## 第四阶段：分镜与片段规划

**进入条件：** 有可拆解的剧情。素材缺失可继续做文本分镜，但必须保留对应缺口。

**处理：**

- **镜头 SH** 是叙事与视听设计单元，描述观看什么、为什么此刻观看，以及人物和摄影机如何运动。
- **片段 CLIP** 是为未来制作组织的交付单元，可包含一个或多个镜头。仅在本轮需要制作交接或片段规划时启用；只做分镜时省略 CLIP 编号、分组表及相关检查。启用后仍只提出暂定分组，不写死每段时长或镜头数量。
- 按 U07，项目未指定目标时长时先结合故事建议时长范围，说明节奏取舍，用户确认后再细化逐镜估时；启用 CLIP 时再分配片段时间。已有明确目标时长直接复用；确认前可继续不依赖目标时长的规划。
- 项目未指定画幅时，按 U07 结合观看用途与故事提出画幅建议，说明构图影响，由用户选择；已有明确画幅直接复用。相关构图在选择前保持候选，选择后按该比例细化。
- 原稿未明确声音或字幕时，按 U07 结合故事提出用途建议并标为待确认，由用户选择后纳入分镜；已有要求直接沿用，原稿文字的改写仍遵守 U02。
- 先按动作、对白、情绪与信息量安排镜头；启用 CLIP 时再分组。较长镜头若未来需要分段制作，保留同一镜头的连续性要求，不把技术分段误写成叙事剪切。
- 不统一限制每段 15 秒，不强制景别循环，不强制每段包含固定数量镜头。时间预算以对白试读、动作过程、停顿和转场为依据；没有实测时标为估计。
- 避免仅用字数判断对白时长。无法容纳内容时提出延长、重新分组或经授权改写的选项。
- 标出空间关系、人物位置、视线与运动方向、道具状态以及前后镜头衔接；启用 CLIP 时再检查片段接点。
- 给原文重点建立 SRC → SH 对应关系；启用 CLIP 时再补 SH → CLIP，并检查片段内连续子镜头区间不重叠、不遗漏，例外须解释。
- 按 V01–V03 设计并核对镜头，结合已确认的 S01 导演意图；有实际创作分歧时再提供可比较方案，记录适用场景及受影响的镜头。

**输出：** 分镜表、时长依据与连续性检查；仅启用 CLIP 时附暂定片段表及相关检查。目标时长未确认时先交付范围建议与节奏取舍，暂不细化逐镜及片段时间。

**检查：** 关键内容有落点；细化时长有用户指定或确认依据；估计总时长与目标差异可解释；动作和对白不超载；没有相互冲突的镜头数量规则。

**已确认依据：** 按具体故事比较方案，不设统一叙事偏好 [U03](references/owner-inputs.md#u03)，视觉方向按 [U04](references/owner-inputs.md#u04) 比选并沿用项目决定，时长按 [U07](references/owner-inputs.md#u07) 先建议范围、确认后细化。**你的补充点：** 本项目其余视听规格、验收 [U08](references/owner-inputs.md#u08)。

## 第五阶段：提示词与素材匹配

**进入条件：** 项目明确需要图片或视频提示词；无提示词需求则跳过。角色、场景或道具等静态资产图直接使用第三阶段的资产规格与提示词；镜头静帧使用对应 SH 的画面描述；视频使用 SH 或已启用的 CLIP 草案。不为提示词额外创建 CLIP。缺少参考素材时只产出带明显占位符的草案，不标为可执行任务。

**处理：**

- 按 U06 使用平台无关写法，每份草案标明“尚未验证”。区分静态图片提示词与视频提示词，只附本项目明确需要的类型；图片描述可见构图和身份细节，视频补充起始状态、动作先后、摄影机运动、结束状态和声音要求。
- 以用户选定风格为准，不内置固定导演风格，不无依据禁止颜色或要求连续切换景别。
- 按提示词类型关联资产 AST、镜头 SH 或已启用的 CLIP，并注明所需参考资产的版本与引用用途；身份参考不能被风格参考替代。
- 跨片段重复使用稳定身份锚点和状态信息，但不宣称重复名字或文字描述就能保证人物一致。
- 当前只使用人可读的资产编号与路径。平台特有引用语法、模型名与工具参数留待未来核实，不伪造调用命令。
- 将缺少素材、剧情未定和参数未核实分别标出，避免把不完整提示词包装成可直接提交的成品。
- 按 V04 检查描述与素材匹配，引用相关项目决定；不得在提示词环节加入上游未确认的剧情、身份或风格变化。
- 声音与字幕沿用原稿明确要求或 U07 已选方案；未选择的用途建议只列待决定项，不作为已确定要求写入提示词。

**输出：** 本项目明确需要的图片 / 视频提示词草案（尚未验证）、相关素材版本匹配表、缺口与冲突。

**检查：** 提示词有明确项目需求，采用平台无关写法并标明尚未验证；忠于已确定剧情；参考对象和版本明确；时间、空间、动作、声音约束不互相矛盾。

**已确认依据：** 按需交付平台无关、尚未验证的提示词草案 [U06](references/owner-inputs.md#u06)，以及按 [U04](references/owner-inputs.md#u04) 比选后确认的项目风格；尚未选择时保留候选状态。**你的补充点：** 现成实作案例（如有）、素材 [U05](references/owner-inputs.md#u05)、声音与规格 [U07](references/owner-inputs.md#u07)。

## 第六阶段：制作任务与成本计划（不提交）

**进入条件：** 用户需要完整制作规划；已有片段与素材依赖可整理。

**处理：**

- 列出拟制作产物、输入版本、目标规格、依赖和缺口，状态一律为计划、待补充或待核实。
- 不固定模型、并发数或分辨率。未来选择平台后，才核对实时能力及可接受参数；当前没有核实依据就不写成有效配置。
- 当前生成数量为 0，生成预算为 0；不要把“尚未查询费用”写成免费。
- 仅预留未来报价字段：平台、模型、时长、分辨率、数量、逐条与总费用、余额、扣费方式、费用依据及上限。没有可靠报价时保持待核实，不能用真实生成试探价格。
- 未来即使接入制作，也必须遵守用户当时适用的积分门禁：即梦 / 可灵 CLI 视频每次提交、重新生成或重试均需针对本次任务重新报价并取得明确批准；参数、数量或费用变化重新批准，免费或无限额度亦须说明和确认。
- 规划故障处理：响应不确定时先查原任务；重复失败没有新证据、无实质修改或达到预算时停止该部分，不盲目重投。此处仅写计划，本版不执行查询或重试。

**输出：** 未提交的制作任务表、未来能力核实与报价清单。

**检查：** 未产生外部任务；计划没有被标成已提交或已生成；不存在无限重试或默认批量扣费规则。

**你的补充点：** 规格 [U07](references/owner-inputs.md#u07)、未来预算与重试上限 [U09](references/owner-inputs.md#u09)。U09 不阻塞本草稿完成。

## 第七阶段：规划交付与成片验收设计

**进入条件：** 本轮授权范围内的文档已整理；未决定项和未执行阶段仍可保留。

**本版实际交付：**

- 按 U07 默认以一份项目工作表分章节组织本轮所需内容；按 U08 先检查一致性，再将约定的文档、检查结果、问题与待定项集中提交，由用户验收。
